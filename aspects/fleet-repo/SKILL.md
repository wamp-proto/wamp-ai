# fleet-repo

The contract for a repository that **records the provenance of a fleet**. Every rollout
over the fleet leaves one record, `rollouts/<id>/rollout.toml`, written by the rollout
engine at execute and close-out: the aspect and its revision, the inventory commit the
members were read from, and per member the issue, the commit that applied the change,
the maintainer's land merge and the convergence proof. `rollouts/README.md` is an index
the engine generates from the records. A fleet repository is a member of its own fleet,
so it declares this aspect.

The records are evidence. This aspect makes the fleet repository's own CI catch a
record that was edited by hand, or one that claims more than it proves.

## Rule 1: the rollout records (implemented, check only)

For every `rollouts/<id>/` that contains a `rollout.toml`:

| # | rule | check |
|---|---|---|
| 1 | `schema` | `rollout.toml` parses; `schema = 1` (another schema is a FAIL that names it) |
| 2 | `id` | `id` equals the folder name, of the form `YYYYMMDD-<aspect>[-N]` with the record's own `aspect` |
| 3 | `status` | one of `planned`, `issues-filed`, `executed`, `landed`, `converged` |
| 4 | `fleet` | this repository's slug: one of its GitHub remotes' `org/name`; without a GitHub remote, the name part must equal the directory name |
| 5 | `revs` | `[provider] repo` present; `[provider] rev`, `[apex] rev` and every member and decision commit are full 40-character lowercase SHAs |
| 6 | `members` | each member has `repo`, `slug`, `base`, `changes`, `changeset`, `changeset_sha256`, and `changeset_sha256` is the SHA-256 of `changeset` |
| 7 | `promises` | from `issues-filed` every member has an `issue`; from `executed` a `commit` (or `stop_commit`, when execute stopped on a decision); from `landed` a `merge`; at `converged` a `proof_rev` and `proof_changeset_sha256` equal to the digest of the empty ChangeSet, the SHA-256 of `[]` |
| 8 | `decisions` | every recorded decision has `decided_by` equal to `human` or `agent` |

Checks 6 and 7 need nothing but the record: a changeset edited after it was hashed, and
a `converged` record without proof of convergence, are both caught offline.

**Not checked:** whether the recorded commits exist in the member repositories. That
needs the network or a clone of every member; the rollout engine's close-out proves it,
and `proof_rev` is that proof.

## Rule 2: the index (implemented, check only)

| # | rule | check |
|---|---|---|
| 1 | `index-header` | `rollouts/README.md` exists and starts with its generated-file comment |
| 2 | `index-set` | the rollouts the index links (`[`<id>`](<id>/rollout.toml)`) are exactly the record folders: none missing, none extra, none twice |
| 3 | `index-rows` | per row, `aspect`, `status` and the fleet issue agree with the record, and the link points at the row's own folder |
| 4 | `index-order` | rows are newest first by id |

**Consistency, not byte equality.** The index renderer belongs to the rollout engine.
Re-rendering it here would be a second copy that drifts; so column layout, member links
and the "changes" and "aspect rev" cells are not checked. The likeliest drift - a
close-out changed `status` and the index was not regenerated - is.

A fleet repository with **no rollout yet** is one WARN line, not a FAIL.

## Both rules are check only

The records are written once by the rollout engine and never rewritten by an aspect;
the index is regenerated by the engine. So `reconcile.py` always returns an empty
ChangeSet, and `check.py` reports.

## Scripts

Standalone, standard library only (Python 3.11+), importing nothing from any engine:

- `scripts/check.py <repo>...` - findings per repository; exit 1 on any FAIL.
- `scripts/reconcile.py --json <repo>...` - the ChangeSet: always empty, with a digest.
- `scripts/_fr.py` - the shared logic.
